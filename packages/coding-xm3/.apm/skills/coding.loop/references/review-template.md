  指摘一覧の正本。計画ファイルと同じディレクトリに置く。
  例: login-home_1.md → login-home_1_review.md

  更新ルール:
  * 通し番号は単調増加。既存エントリの番号は変えない

    診断・確認結果を親へ返し、親が Status を更新する
  * 通常レビュー（software-design-reviewer）と DO NOT 監査（software-design-audit）は
    指摘作業の前に必ず本ファイルを閲覧し、出典が違っても実質同一の指摘を新規に出さない
  * Status 対応済み の再指摘は禁止
  * 再レビュー待ち は Review Agent が差分検証のみ述べ、新規エントリを増やさない

  Status 凡例（この3値のみ。旧「再レビュー」「リジェクト」「不採用」は Status に使わない）:
  * 要対応 … Review Agent によって、要対応と診断された（Main Agent の処分待ち）
  * 再レビュー待ち … Main Agent が、レビュー結果を計画へ反映した（Review Agent の確認待ち）
  * 対応済み … 採用経路で Main / Review 双方が承認した、または Main が提案を不採用とした
    → ゲート通過対象。再指摘禁止

  遷移の目安:
  * （新規）Review 診断 → 要対応
  * Main が採用・計画反映 → 再レビュー待ち → Review が解消を確認 → 対応済み
  * Main が不採用 → 対応済み（本文に「提案を不採用とした: {理由}」を残す。Review 確認なし）
  * Review が未解消と判断 → 要対応 に戻す（採用経路の 再レビュー待ち のみ）
