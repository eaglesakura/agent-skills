# Firebase IAM（プロジェクトアクセス）

## 概要

本ドキュメントは [Manage project access with Firebase IAM](https://firebase.google.com/docs/projects/iam/overview) を蒸留したものである。Firebase 固有ロールと GCP IAM の関係、Console に見えないサービスアカウントの確認を扱う。

* 正本: <https://firebase.google.com/docs/projects/iam/overview>
* 関連: [`../cloud.google.com/0003-iam.md`](../cloud.google.com/0003-iam.md)

## 基本ロールより Firebase 事前定義ロールを使う

Owner / Editor / Viewer の基本ロールより、Firebase-level / product-category / product-level の事前定義ロール、必要ならカスタムロールで最小権限にする。

### 基本ロールより Firebase 事前定義ロールを使うの補足

* 利点: Analytics や個別プロダクトだけの権限に絞れる
* 注意点: ロール変更には `resourcemanager.projects.setIamPolicy`（実質 Owner 相当）が必要
* 適用範囲: 人間メンバー、グループ
* 例外: 組織配下で Owner が不在の場合は組織管理者に依頼

### 基本ロールより Firebase 事前定義ロールを使うの実装例

```text
チェック
* 本番データ閲覧は Viewer / Firebase Viewer 系
* デプロイ担当は必要な product ロールのみ
* Editor の全員付与をやめる
```

## Firebase Console と Cloud Console の両方でメンバーを確認する

Firebase Console の Users and permissions は基本／Firebase 事前定義ロールの人間中心である。サービスアカウントは Google Cloud の IAM ページで確認する。

### Firebase Console と Cloud Console の両方でメンバーを確認するの補足

* 利点: SA の過剰権限を見落とさない
* 注意点: 「Console に誰もいない＝安全」ではない
* 適用範囲: 定期 IAM 棚卸し
* 例外: なし

### Firebase Console と Cloud Console の両方でメンバーを確認するの実装例

```text
棚卸し
1. Firebase Console → Users and permissions
2. Cloud Console → IAM & Admin → IAM（SA 含む）
3. 不要プリンシパルと広いロールを削除
```

## ナレッジベース

### DO: 本番プロジェクトの人間アクセスを事前定義ロールで最小化し、SA も Cloud IAM で監査する

```text
# 推奨
humans: Firebase predefined roles
sas: Cloud Console IAM review
policy_admins: few Owners only
```

### DO NOT: Firebase Console だけ見て Editor を配り、SA を無視する

* 理由: 公式が SA は Cloud Console 参照だと明記している
* 理由: Editor は Firebase 全般への広い権限になる

```text
# DO NOT: 開発者全員に Editor

# DO: グループ + 製品ロール + SA 棚卸し
```
