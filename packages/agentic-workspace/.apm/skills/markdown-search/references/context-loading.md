# Context ロードの段階設計

全文をいきなり Context に載せるとトークンを浪費し、関連箇所の判断も鈍る。
次の 3 段階で深さを上げる。

## Stage 1 — 見出し TOC（行範囲付き）

* 目的: 文書構造と「どこからどこまでが一塊か」だけを把握する
* 出力例: `path/to/file.md:617-701	## ナレッジベース`
* 本文はまだ読まない
* 内容（SHA-256）が同一のファイルが複数 path にあるときは、先に現れた 1 件だけを候補にする（コピーの二重ロード防止）

終端ルール:

* 見出しの範囲は、**同レベル以上の次見出しの直前**まで（子見出しを含む）
* 既定で末尾の空行は trim する
* コードフェンス内の `#` 行は見出しではない

## Stage 2 — 指定範囲のみロード

* TOC で当たりを付けた `start-end` だけを読む
* 1 見出し、または親見出し 1 塊（子含む）を単位にする
* 複数ヒット時は関連度の高い範囲から順に読む

## Stage 3 — 文書全体

* Stage 2 だけでは横断関係・前提・用語定義が足りないと判断したときだけ全文を読む
* 「念のため全部」は避ける

## 使い分けの目安

| 状況 | 段階 |
| --- | --- |
| どの文書が関係するか分からない | Stage 1（複数ファイル TOC / `--max-level 2`） |
| DO / DO NOT の条文が必要 | Stage 1 `--grep` → Stage 2 で当該範囲 |
| 1 節のルールと例が必要 | Stage 2 |
| 章全体の流れ・用語の定義が必要 | 親見出しの Stage 2、なお不足なら Stage 3 |
