# 要件定義

## 概要

このコマンドは、要件をもとに関連アーキテクチャを確認し、実装方針とファイル構成の提案を作成するためのものである。既存の実装パターンを参照しながら、アーキテクチャ原則に準拠した提案を行うことを目的とする。

* Coding-Commandsのステップ1である
  1. `/coding.requirement`
  2. `/coding.design`
  3. `/coding.execute`

## 用語

* 計画ファイルとは、 `.ai-agent/plan/*.md` に保存された「要件定義・詳細設計・実装手順」等が記載されたファイルである

## 入力値

* 要件定義情報を含んだプロンプト

## 出力

* 実装計画を記載したファイルを `.ai-agent/plan/{計画名}.md` に保存する
  * 文脈に合わせて、適切なファイル（新規、もしくは上書き）へ保存する
* 出力フォーマットは [requirements.md](../extra/coding/requirements.md) に準ずる

## ガードレール条項

* [ ] 計画ファイルとレビュー関連ファイルの作成・更新以外のファイル変更を行わないこと
* [ ] 以後、ユーザーの発言はすべて計画に対する内容であると常に意識すること

## 作業手順

### ステップ1. 要件定義

* [ ] 宣誓を行う

    ```text
    宣誓
    
    私は要件定義を行います。
    必要なSKILLは積極的に活用し、良き計画の実現のために提案を行います。

    このコマンド実行以後、私は `要件定義モード` に入ります。
    ハーネスが適用され、計画ファイルのみを更新します。
    ユーザーが明示的に指示するまで、詳細設計と実装は行いません。
    ```

* [ ] 事前に確認すべき資料を、SKILLによって深い調査を行い、整理する
  * 関連するディレクトリ、package、技術資料、関連する要件定義等を確認する
  * 文脈に基づき、関連したSKILLを適用する
* [ ] ユーザーから示された要件定義と関連が考えられる情報を整理する

### ステップ2. レビュー

* [ ] 作成・更新された要件定義を `/coding-assistant.requirement-reviewer` Sub Agentによって批判的視点に基づき、レビューする
  * テストケースの不足が無いか
  * 要件に矛盾や不足事項がないか・暗黙的要件が隠れていないか
  * シニアエンジニアによって実装可能な粒度の要件が定義されているか
  * 適切な書体であるか
    * 出力フォーマットは [requirements.md](../extra/coding/requirements.md) に準じているか
    * 凡例に従って、ファイルツリーに `[編集]` 等のタグを付与しているか
* [ ] レビューが完了するのを待つ
* [ ] 指摘内容を整理して出力する

    ```markdown
    # 指摘内容

    ## {指摘内容のサマリ}

    {詳細}

    ## {指摘内容のサマリ}

    {詳細}
    ```

### ステップ3. 次ステップのサジェスト

* [ ] レビュー内容に従い、再度要件を整理して計画ファイルを更新する
* [ ] ユーザーに対し、下記のフォーマットで質問を行う

    ```markdown
    # 要件定義結果

    {サマリ}

    <!-- 
    要件定義の結果、ユーザーとの対話が必要な内容を列挙する
     -->
    要件定義の不足を整理します。
    下記の質問に回答をお願いします。

    ## 質問1
    
    <!-- 
    自由入力、もしくは推奨値の選択.
    推奨する提案がある場合は、下記のように答えやすい形式にする
     -->
    ### 提案A {サマリ}
    
    {詳細}

    ### 提案B

    {詳細}
    
    ## 質問2

    {質問のサマリ}

    <!-- 
    自由入力、もしくは推奨値の選択.
    推奨する提案がある場合は、下記のように答えやすい形式にする
     -->
    ### 提案A {サマリ}
    
    {詳細}

    ### 提案B

    {詳細}
    ```

* [ ] ユーザーに次の旨を告げる

    ```markdown
    私は `要件定義モード` です。
    宣誓に従い、ユーザーが明示的に指示するまで、詳細設計と実装は行いません。
    計画ファイルは [{ファイル名}](path/to/markdown.md) です。
    続きの指示は、全て要件定義についての指示として解釈します。

    例: `計画の修正プロンプト...`
    例: `質問の回答...`
    例: `/coding.requirement 要件の修正を行い、再レビュー`
    例: `/coding.design 要件を承認し、詳細設計を行います`
    ```
