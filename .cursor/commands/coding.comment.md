# コメント粒度の適正化

## 概要

* このコマンドは、指定範囲のコメントの粒度をプロジェクト方針に合わせて適正化する

## 入力

### 必須: 対象コードのスコープ

* ファイル全体、指定関数等、コメントの粒度の適正化対象を判断する

## 手順

1. 対象コードの言語や範囲から、必要なSKILL及びドキュメントのロードを行う
    * Golang用のコーディング規約、dart用のコーディング規約、等
2. コードコメント粒度を改善する
    * コードコメントは、指定されない限り `追加` のみ行う
3. コードコメントの追従
    * 指定範囲のコード、及び推測される関連コードが、実態に即しているか確認する

## ナレッジ

## 主語の有無

* 基本的にコードコメントに主語は不要である。コメント箇所を指すことが自明であり、多くのパターンにおいて冗長となるためである.
* 主語が冗長であると判断した場合、削除して良い

## 日本語と英語のスペーシング削除

* コードコメントの基本は日本語の技術文である
* 日本語文として不自然なスペーシングを行わない

```text
// ✅️ DO
// 日本語とEnglishが混ざっていても、不自然なスペースを空けない。
// `OS` 等の引用符の前後ではスペースを開けて良い。
//
//
// ⚠️ DO NOT
// 日本語 と English が混ざっていても このような スペーシングは 不自然である。
```

## 改行

* 基本的に1文ごとに改行を行う。
* １文が非常に長くなる場合は、適宜追加で改行を行って良い。

### 改行の例外

* exampleについては、コメント規約ではなく、コーディング規約に基づいた改行を行う

### Internal / Privateの判断

* Internal / Private等、対象のスコープによってコメント量を増減せず、すべてPublicと同等に対応する

### 関数(メソッド)のexample

* 関数(メソッド)のコードコメントには、言語の記法に沿ったexampleを用意する
