# エンジニア / 詳細設計

- ソフトウェア開発における、 `詳細設計` を行うSKILL
- このSKILLの主題は `詳細設計` を行い、ユーザーに適切な変更差分を提案することである

## 設計の基本

- 積極的にSKILL/ドキュメントをロードする
- SKILL及びドキュメントの `DO` `推奨` に従って提案する

## 入力値

### 必須: 要件定義 / 既存の詳細設計情報

- 実装をするために、可能な限り詳細な要件定義を事前に行うことが望ましい
- 関連するプロンプトも同時に与えることで、ユーザーの意図を適切に判断する
- 既存の計画ファイルが存在する場合は、ファイルをロードする

## ガードレール条項

- このSKILLは詳細設計そのものを役目としており、**実際のコードを変更しない**

## 実行手順

### ステップ1. 要件確認

- [ ] 与えられた要件定義や実装計画から要件定義を理解する
- [ ] 追加で与えられた改善プロンプトを理解する
- [ ] 要件を満たすための変更箇所を特定する

### ステップ2. 関連ドキュメント確認

- [ ] 計画及びプロンプトから、ユーザーからの要件を確認する
  - 不明点、もしくは曖昧な点があれば、ユーザーに確認を取り、詳細化する
  - 下記は必ず調査する
    - [ ] アーキテクチャレイヤードキュメント
    - [ ] コーディング規約
- [ ] 関連SKILLとドキュメントをロードする

### ステップ3. 変更提案

- [詳細設計テンプレート](../../extra/coding/design.md) をロードし、出力フォーマットを把握する
  - プロンプトの指示に応じて、多少のフォーマット変更は許容される
- [ ] 変更すべき内容を考案する
  - [ ] 具体的な変更差分を提示する
  - [ ] 具体的な変更差分に基づいたファイルツリーを挿入する
- [ ] 変更すべき内容を整理し、理解する

#### 満たすべき品質

- `ジュニアエンジニア` がコーディングを行えるレベルの詳細が必要である
  - [ ] ファイルツリーによるサマリ
  - [ ] わかりやすい差分
  - [ ] 詳細なコードコメント
  - [ ] 十分なテストコード提案
  - [ ] ステップ・バイ・ステップで実装可能な手順提案

### ステップ4. 指定フォーマットに基づいた出力

- 出力内容の再チェックを行う
- [詳細設計テンプレート](../../extra/coding/design.md) に基づいて出力を行う
